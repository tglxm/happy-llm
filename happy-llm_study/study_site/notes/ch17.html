大模型生成 Token 的方式有哪些？

SUMMARY · 章节总结

本章对比大模型生成 Token 的四种解码方式。贪婪解码每步取概率最大的 token，最快且确定，却易陷局部最优、易重复，适合确定性任务。采样解码按概率分布随机抽取，用 Temperature 缩放 logits（越大越平滑、越小越尖锐、趋近 0 等价贪婪）并配合 Top-k 只留概率最高的 k 个候选，代价是需调参、结果不确定。束搜索每步维护多条候选路径并按累积对数概率筛选，束宽为 1 时等价贪婪，越大质量越高但开销越大。投机解码用小模型先写草稿、大模型批量验证并握有否决权，可减少九成以上大模型前向传播而不降低质量，本质是用计算资源换时间，草稿通常 2 到 10 个 token。

KEY POINTS · 核心要点
  • 贪婪解码每步取概率最大的 token（torch.topk k=1），结果确定、速度快但易陷局部最优、缺多样性、易产生重复。
  • 采样解码基于概率分布随机选择，用 Temperature 缩放 logits（>1 更平滑、<1 更尖锐、趋近 0 等价贪婪）并配合 Top-k 过滤掉低概率候选。
  • _random_sample 的流程是温度缩放 → Top-k 过滤 → softmax 归一化 → 随机采样。
  • 束搜索每步保留 N 条候选路径并按累积对数概率筛选，束宽度=1 时等价于贪婪解码，宽度越大质量越高但计算与内存开销越大。
  • 投机解码用「小模型生成草稿、大模型批量验证」的方式，大模型拥有最终否决权，可减少 90%+ 大模型前向传播且不降低生成质量。
  • 投机解码的草稿长度通常控制在 2-10 个 token，并按接受率动态调整以平衡加速效果。
「采样解码不是选择概率最大的token，而是基于模型的概率分布进行随机采样。」
「束搜索是一种启发式搜索算法，它在每一步生成时保留多个候选序列（束），而不是只选择一个最佳序列。」
实践建议：对同一 prompt 分别用贪婪解码、temperature=0.8 加 top_k=50 采样、束宽度 3 生成，比较结果的确定性、多样性与重复情况。

Q1. 关于几种解码方式的参数，下面哪一项说法是正确的？

💡 摘录写明 temperature>1 分布更平滑、<1 更尖锐、趋近 0 等价贪婪解码，束宽度=1 等价贪婪解码；Top-k 只保留概率最高的 k 个，k 越大保留越多、被过滤的越少，故其余三项都说反了。

Q2. 投机解码用小模型先生成草稿，为什么能大幅加速却「不降低生成质量」？

因为大模型会一次性批量验证整个草稿序列并拥有最终否决权，只有它认可的 token 才被保留，被拒绝处由大模型重新生成，最终输出仍由大模型决定；加速来自减少九成以上的大模型前向传播，本质是用计算资源换时间。

💡 对应验证阶段、关键优势与总结三节：草稿长度通常控制在 2-10 个 token，并按接受率动态调整。

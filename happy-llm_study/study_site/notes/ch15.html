S1: Thinking Budget with vLLM

SUMMARY · 章节总结

本章介绍用 vLLM 复现 s1 论文的测试时间缩放：通过设定思考预算控制推理时长，预算增加时性能明显提升。论文用大模型答题判定难易，消融发现未达预算时插入 Wait! 等特定词能引导更深入思考，「Wait, Wait」效果最好。实现上先算输入 token 数把预算换算为每轮最大生成量并设置停止符；每轮生成后把文本拼回输入、末尾追加 Wait! 迫使继续思考，思考 token 超预算即停止；达到预算后再让模型总结输出答案。实测发现插入 Wait! 未必带来多路径尝试或反思，反而可能重复生成、超出预算，推测与测试模型仅 14B 有关，强行引导甚至会让模型「一条道走到黑」。

KEY POINTS · 核心要点
  • Test-time scaling 通过调整推理阶段的思考预算提升复杂推理问题的效率与准确率，预算增加时模型性能明显提升。
  • 论文用 Qwen2.5-32B-Instruct 答题判定难易（答对为简单、答错为复杂），消融发现插入 Wait! 等特定词能引导更深入思考，「Wait, Wait」效果最好。
  • vLLM 实现中 run_thinking_budget_sample 先算输入 token 数、把预算换算为每轮 max_tokens，并在 SamplingParams 里设置 stop 参数。
  • 每轮生成后把文本拼回输入、末尾追加 Wait! 迫使模型继续思考，一旦思考 token 数超过预算即停止迭代。
  • 达到预算后再用一份 max_tokens=4096 的 SamplingParams 让模型基于思考过程总结输出最终答案，并打印迭代次数与各类 token 统计。
  • 实测发现插入 Wait! 未必带来多路径尝试或反思，反而可能重复生成、超出预算，作者推测与测试模型仅 14B 有关，强行引导可能让模型「一条道走到黑」。
「就是说对于一些复杂问题，需要用推理链来解决的问题，我们可以通过调整模型的思考预算来提高推理效率和准确性。」
「例如，在某些情况下，就算插入了Wait!，模型并不会按照论文中所示进行多种不同方式尝试解答，或是反思之前的思考过程是否正确。」
实践建议：用 vLLM 跑 s1.py，对同一道复杂题对比思考预算 512 与 2048 下的迭代次数、思考 token 数与答案，观察是否出现重复生成或超预算。

Q1. 在 vLLM 版 thinking budget 的实现里，每轮迭代把生成文本拼回输入后，代码在末尾追加 Wait! 的目的是什么？

💡 摘录说明每轮把生成文本拼回输入、并在末尾追加 Wait! 是为了引导模型更深入地思考，且只有思考 token 数超过预算才停止迭代；stop 参数在 SamplingParams 里单独设置，输入 token 数在函数开头就已计算。

Q2. 作者在结果分析中发现，强行插入 Wait! 引导思考时出现了哪些与论文预期不符的现象？可能原因是什么？

模型未必像论文所示尝试多种解法或反思已有思考，反而会重复生成相同内容、导致思考 token 数超出预算；作者推测这与测试模型只有 14B 参数、思考能力受限有关，并认为强制插入特定词可能让模型产生「一条道走到黑」的想法。

💡 对应结果分析一节的观察：小模型能力受限、重复生成超预算，以及强行引导的副作用。

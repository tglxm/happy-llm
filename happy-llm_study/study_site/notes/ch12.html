Transformer 整体模块设计解读

SUMMARY · 章节总结

本章结合 PyTorch 源码从整体设计拆解 Transformer 各模块。因模型对词序不敏感，须把位置向量加到输入嵌入；位置编码要满足确定性、相对关系一致性和泛化能力，故用正余弦函数使偏移位置可写成已知位置的线性组合，从而推广到更长句子，并靠残差连接把位置信息传到深层。接着梳理顶层五个参数与四个类的模块化结构，前向过程区分填充掩码与上三角的因果掩码，点明模型本质是按词自回归解码。再讲多头注意力把 512 维拆成八个 64 维头、前馈网络先升维到 2048 再降回 512、解码器交叉注意力以编码器输出为键值，最后落到缩放点积注意力除以根号维度以稳定 Softmax、输出为值的加权和。

KEY POINTS · 核心要点
  • 位置编码须满足确定性、相对关系一致性、泛化能力三前提，故用 sin/cos 使 pe(pos+k) 可写成 pe(k) 的线性组合以推广到更长序列；并靠残差连接让初始位置信息 x0 始终存在于每层输出、不随深度丢失。
  • PyTorch 顶层 Transformer 由 TransformerEncoderLayer / TransformerEncoder / TransformerDecoderLayer / TransformerDecoder 四个 class 模块化组成，核心超参为 d_model=512、nhead、默认 6 个 encoder block、dim_feedforward=2048。
  • forward 有两类 mask：encoder 的 padding_mask 把无效位置在 softmax 前置负无穷使其概率为 0，decoder 的因果 target mask 是上三角矩阵，保证只依赖当前词左侧、避免 output embedding 全给造成 x→x 的 identity 映射；Transformer 本质自回归逐词解码。
  • Encoder 每 block 为多头自注意力 + FFN，各接残差与层归一化（原始论文为 post-LN）；FFN 做 512→2048→512、对每位置独立且位置间参数共享，负责同位置不同维度融合，注意力负责位置间信息交流。
  • 多头注意力把 512 维按线性变换重组为 8 个 64 维头各自算 attention 再 concat 回 512；Decoder 比 Encoder 多一个交叉注意力，用 decoder MHA 输出作 query、encoder 输出 memory 作 key/value，故需 3 个 norm 与 3 个 dropout。
  • Scaled Dot-Product Attention 在 QK 后除以根号 d_k 以减小方差、稳定 Softmax，输出是 Value 按 Query-Key 相似度经 Softmax 权重的加权和；代码实现中一个 mask 对应自注意力、两个 mask 对应交叉注意力。
「这种模块化的设计体现了软件工程的最佳实践：单一职责原则和组合优于继承的思想。」
「FFN实际上做的是embedding相同位置不同维度间的融合，在每个位置内部对该位置的不同特征维度进行融合，注意力机制负责位置间的信息交流。」
实践建议：对照 torch.nn.Transformer 源码手写一个 Scaled Dot-Product Attention，分别打印自注意力（一个 mask）与交叉注意力（两个 mask）的 causal / padding mask，验证上三角因果掩码确实屏蔽了当前词右侧的 token。

Q1. 关于 decoder 的因果 target mask，下列说法正确的是？

💡 原文「因果掩码mask」指出 output embedding 若全给会变成 identity 映射，故用上三角矩阵只给当前词左侧；标记样本长度、softmax 前置负无穷是 padding_mask 与 memory mask 的职责。

Q2. 为什么位置编码采用 sin/cos 三角函数，而不是把序列按 0~1 等分？

等分法会让同一位置在不同长度序列里得到不同编码，违反确定性原则；sin/cos 使 pe(pos+k) 能写成 pe(k) 的线性组合，满足相对关系一致性，并能外推到训练时未见过的更长序列。

💡 位置编码还须满足泛化能力，且靠残差连接让底层位置信息 x0 始终存在于各层输出、不会随网络加深而消失。

第五章 动手搭建大模型

SUMMARY · 章节总结

本章把理论落成代码，主线是从零搭建模型、训练分词器、再预训练并微调一个八千万参数小模型。实现按依赖顺序展开：用配置类管好维度、层数、头数等超参，依次实现归一化、注意力、前馈层与解码层并堆叠成模型，每步用输出张量形状自测。注意力用分组查询注意力提效、复制键值头，并预计算旋转位置编码；前馈层用门控激活相乘。分词器比较三类方案后，用工具库按五步训练字节对编码并配好对话模板与特殊标记。训练阶段：预训练数据集把词元序列前后错位拆成输入与标签，微调数据集用损失掩码只在助手回复段计算损失，生成函数迭代采样新词元。实测批量为四约需7G显存，八卡下预训练四十六小时。

KEY POINTS · 核心要点
  • 用继承 PretrainedConfig 的 ModelConfig 管理 dim、n_layers、n_heads、vocab_size、max_seq_len 等超参，按 RMSNorm→Attention→MLP→DecoderLayer→堆叠 LLaMA2 的顺序逐模块实现并用输出形状（如 torch.Size([1,50,768])）自测。
  • Attention 采用 GQA 提升效率，靠 repeat_kv 把 K/V 头扩展到与 Q 一致，并预计算旋转嵌入（RoPE）的频率外积注入位置信息。
  • MLP 由 w1 经 SILU 与 w3 门控相乘、再过 w2 和 dropout 构成，RMSNorm 用均方根归一化乘可学习 γ 且不改变张量形状。
  • Tokenizer 比较词、字符、子词三类后选用 tokenizers 库按五步训练 BPE，需配置 chat_template（对齐 Qwen2.5）、special_tokens 并写 tokenizer_config.json 等文件。
  • 训练八千万参数小 LLM 时，PretrainDataset 把 input_id 拆成 X（前 n-1）与 Y（后 n-1），SFTDataset 用 generate_loss_mask 只在助手回复段计算损失。
  • generate 取序列最后位置的 logits 生成新 token 并迭代追加，实测 batch=4 约需 7G 显存、533 小时，8 卡 4090 下 Pretrain 46 小时、SFT 24 小时。
「在 generate 方法中，我们首先获取序列中最后一个位置的 logits，然后基于这些 logits 生成新的 token。」
「实测 Pretrain batch 为 4 的情况下只需要 7G 显存，训练时长预计 533 小时。」
实践建议：按 5.1 顺序复现 RMSNorm、Attention、MLP 并用 torch.Size([1,50,768]) 逐层校验，再把 ModelConfig 的 n_layers 或 dim 调小、batch 调到 4，观察显存与训练时长变化。

Q1. 在本章的 SFTDataset 中，generate_loss_mask 生成的 loss_mask 作用是什么？

💡 摘录说明 SFTDataset 与 PretrainDataset 的 X、Y 一样，区别正是多了 generate_loss_mask：遇到助手起始标记才开始计算损失、到结束标记为止，从而只对当前轮对话内容算 loss；A 是 PretrainDataset 的做法，C 是 generate，D 是 repeat_kv。

Q2. 本章从零实现 LLaMA2 的模块顺序是怎样的？RMSNorm 和 GQA 分别解决什么问题？

顺序为超参 ModelConfig→RMSNorm→LLaMA2 Attention（repeat_kv + 旋转嵌入）→MLP→DecoderLayer→堆叠成完整模型，每层用输出形状校验。RMSNorm 用均方根归一化稳定深层训练且不改变形状，GQA 通过共享与复制 K/V 头提高效率、节省显存。

💡 可补充：MLP 用 w1+SILU 与 w3 门控相乘；原文提到只有 70B 用了 GQA，但本章为效率在所有规模都采用。

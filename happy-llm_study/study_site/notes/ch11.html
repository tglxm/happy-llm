微调 0.6B 小模型有什么意义？

SUMMARY · 章节总结

本章回答现实问题：大模型 API 已足够强，为何还微调 0.6B 小模型。作者用三问决策——数据是否敏感、任务是否刚需推理链、API 并发与资金消耗：敏感数据应本地部署，简单高并发任务微调小模型以省钱，只有困难且刚需推理链才用 API 以免上下文爆显存。案例是从投诉文本抽取姓名、住址、邮箱与投诉问题，几百万条数据调大模型要花几万块且不能出外网，故微调 Qwen3-0.6B 兼顾高并发、不泄漏、效果与省钱。随后给出 SFT 数据格式、Qwen3 模板、LoraConfig、训练参数与 SwanLab 记录等实操链路。结论是选型应由数据、任务与成本决定，而非一味求大。

KEY POINTS · 核心要点
  • 以三问决策：数据是否敏感、任务是否刚需推理链、API 并发与资金消耗；敏感数据本地部署、简单高并发任务微调小模型（默认单卡 4090），困难且刚需推理链才用供应商 API 以免上下文爆显存。
  • 案例是从投诉文本抽取姓名/住址/邮箱/投诉问题，几百万条调用最强模型要花几万块且数据不能出外网，故微调 Qwen3-0.6B 兼顾高并发、不泄漏、抽取效果与省钱。
  • SFT 数据为 instruction/input/output 三字段，目标是让模型理解并遵循用户指令；Qwen3 为混合推理模型，可手动开关 thinking mode。
  • LoraConfig 关键参数：task_type（decoder_only 多为 CAUSAL_LM）、target_modules（attention 层）、r、lora_alpha/r 缩放（示例 32/8=4 倍）、lora_dropout；示例可训练参数约 0.8395%（5,046,272 / 601,096,192）。
  • 用 SwanLab 做训练可视化、超参记录与实验对比，呼应「模型训练更像实验科学、一个优秀模型背后是成千上万次实验」。
「对于问题3，如果任务很简单，且调用的大模型API并发量很高，那我建议微调一个特定任务的小模型，本地部署。」
「有监督微调的目标是让模型具备理解并遵循用户指令的能力。」
实践建议：用几十条自造的投诉文本按 instruction/input/output 构造 SFT 数据，在单卡上以 LoRA 微调 Qwen3-0.6B 做信息抽取，并用 SwanLab 记录 loss、对比不同 r 与 lora_alpha 的效果。

Q1. 按作者的三问判断，哪种场景最适合直接调用供应商的大模型 API，而不是本地微调小模型？

💡 原文对问题 2 的回答指出，场景困难且刚需推理链时可用供应商 API 以保证推理链上下文不爆显存；数据敏感、消除泄漏风险应本地部署，简单高并发省钱则对应微调特定任务小模型。

Q2. LoRA 配置里 lora_alpha/r 决定什么？本章示例的比例是多少？

lora_alpha 是缩放参数，与秩 r 一起决定 LoRA 更新的强度，实际缩放比例为 lora_alpha/r；示例中为 32 / 8 = 4 倍。

💡 此外 r 决定低秩矩阵维度、较小的 r 参数更少，本例可训练参数约 5,046,272 / 601,096,192 ≈ 0.8395%。
